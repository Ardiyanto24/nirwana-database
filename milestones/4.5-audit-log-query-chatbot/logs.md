Query `monitoring.chatbot_query_log` -- **cuma 1 baris masuk** (yang sukses), 3 kasus ditolak (403/404/400) yang sudah dites lewat curl SEMUA hilang dari log meski HTTP response-nya sendiri benar.
Encountered: Diinvestigasi -- ternyata bug nyata di FastAPI, bukan bug logic sendiri: `background_tasks.add_task(...)` yang dipanggil sebelum `raise HTTPException` TIDAK PERNAH dieksekusi. FastAPI's exception handler untuk `HTTPException` membangun response error-nya sendiri dari awal saat exception di-raise -- tidak pernah membawa serta objek `BackgroundTasks` yang sudah diisi task di handler yang gagal. Background tasks yang di-attach ke objek `BackgroundTasks` hasil dependency injection FastAPI hanya benar-benar jalan kalau handler **return** response secara normal, bukan raise.
Fix: 3 titik `raise HTTPException(...)` di jalur ditolak diganti `return JSONResponse(status_code=exc.status_code, content={"detail": exc.detail}, background=background_tasks)` -- status code dan body tetap identik ke caller, cuma mekanisme pengirimannya yang berubah (return normal dengan background task di-attach langsung ke Response, bukan raise).
Did (lanjutan): restart server, ulangi 3 tes ditolak -- response HTTP identik ke sebelumnya (403/404/400, body sama). Query ulang `monitoring.chatbot_query_log` -- 4/4 baris masuk dengan detail benar: sukses (row_count=3, access_scope=own_property, resolved_property_id=P01), 400 (denial_reason "employee_id is required...", employee_id=NULL karena memang tidak dikirim), 404 (denial_reason "'nonexistent-view' is not in the reservation whitelist"), 403 (denial_reason "role 'Front Office Staff' is not permitted for domain 'fnb'").
